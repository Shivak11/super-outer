# Company-native system

## Load boundary

Load for visual hierarchy, components, content language, interaction grammar, or
product character. Do not load for behavior already fixed by an explicit local
contract.

## Review

- Revalidate profile pointers and hashes for product, UI, content, and shared
  components. Separate `EXPLICIT`, `OBSERVED`, and `UNKNOWN`.
- Inventory existing primitives and analogous journeys before proposing a new
  pattern. Preserve native geometry, material, vocabulary, and state behavior.
- Use external style only to fill a documented absence. Never copy another
  company's system or treat generic taste as authority.

## Failure probes and proof

Positive: the change extends a verified local pattern. Negative: reject generic
polish that contradicts it. Boundary: two observed precedents conflict, so keep
the uncertainty visible. Verify against source-linked rules and the real surface.

## Recovery

Restore the last native pattern, retain a feature boundary for interpretive work,
and rerun comparison after the router resolves the missing product decision.
