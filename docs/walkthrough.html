What survives
a reload?

You’re making a registration form. A visitor types their email, reloads the page and loses it. Use Super-Outer to tell your coding agent what should happen instead.

1. Run in your project’s terminal 
npx skills add Shivak11/super-outer --skill super-outer
2. Ask Claude Code or Codex in that project
Use super-outer. In my local demo, keep my name and email in the registration form if I reload. Start with a plan only.
What should I see first?

A short plan, with your original files untouched. Look for the form the agent found, the fields it would keep and a reload check. When that matches your intent, say “Make that change in the local demo and run the checks.”

If the skill is missing, check which project and host you selected in the installer. With a copy of the starter open, ask your agent to read skills/super-outer/SKILL.md and plan the example by hand. If it cannot read your form, ask it to name the missing evidence.

Same form, three levels of care

The agent reads the project’s rules, the nearby code and tests, then the behavior it can observe. Its next move depends on who could be affected and how hard the change is to undo.

Tiny

“Fix ‘Submt’ on the button.”

Correct the label, look for the same typo elsewhere and run the cheapest relevant check. A short reply is enough.

Local

“Keep my draft if I reload.”

For this one demo screen, sketch the visit and the return. The agent can recommend browser-only storage and show how it would test it.

Wide

“Delete everyone’s saved registrations.”

Identify the people and data involved, the risks and the recovery plan. The agent asks you to confirm the scope before acting.

A change of audience

“Actually, we’ll use a shared computer.”

Now the next visitor could see Mira’s email.

Your decision. Should a draft survive a short break, or should each visitor start fresh? You know how quickly people switch seats.

The agent’s recommendation. Use a short expiry if visitors need time to return. It adds a little work and a slow visitor may need to retype. If people trade seats immediately, skip draft saving on that machine.

Before building. Agree on the rule and, if needed, the expiry time. Ask the agent to revise the affected journey and check it with a second visitor. The starter supplies no preset timer.

When the agent says “done,” ask which file changed, what it actually tried, and what appeared on screen. A failed check belongs in the reply. Other browsers, phones, accessibility, the real server and delivery to users each need their own evidence.

What connects to what?

You set the scope. The skill gives the agent guidance. Claude Code or Codex enforces tool permissions.

  1. Installer → skill folder

    You run the Vercel skills CLI. It adds SKILL.md and two reading guides covering journeys and evidence. The MIT starter installs text, with no hooks, telemetry, credentials or background service.

  2. Your request + skill → coding agent

    The host uses its normal model service. The agent reads the project it can access, recommends a level of care and explains its choice. If a real trade-off has no safe reversible default, it asks you one question with a recommendation, cost and reason to reconsider.

  3. Your scope → plan or action

    “Plan only” ends with advice. When you request implementation, local work can proceed within that scope. Wide changes call for a plan and confirmation. You can say “Treat this as wide.”

  4. Host permission → tool result

    The host controls which files and tools the agent can use. Review any approval prompt there. If you deny the action, the agent should leave it stopped and explain the gap.

  5. Observed result → your next decision

    The agent reports what changed, what passed or failed, and what it could not verify. Use those observations to accept the change, ask for a fix, or back it out.

When you want to pause

Stop here. Show me which edits belong to this form and what you have checked so far.

If you want to back out, review those edits and ask the agent to undo just its form change. Have it check the original behavior again. For wide changes, ask how recovery would work before approving the change.

If a tool was denied

The agent should respect the refusal, leave the blocked step unverified and continue only with work you permitted. A skill file cannot grant access. If all you have is a recommendation, the form is still unverified.

What the offline grader checks

In a copy of the repository with Node.js, run:

node evals/check.mjs --self-test

Look for “Self-test passed for 6 fixtures, including negative controls. No model called.” This exercises the separate grader with expected and deliberately wrong answers. It collects nothing from your session.

For a model check, a maintainer supplies a synthetic prompt to a fresh session, saves the response, grades its structure and reads the prose against a rubric.

What the initial evaluation found

In fresh, tools-disabled Claude Code sessions, the draft-reload response passed 6 of 6 structural checks. The typo and denied-read responses each passed 5 of 6. Both misplaced one evidence-limit tag. Codex CLI did not start, so there is no Codex model result.

These spot checks leave model reliability and the effect of installing the skill unmeasured. The original receipt is in docs/evaluation-receipt.md in the repository.
