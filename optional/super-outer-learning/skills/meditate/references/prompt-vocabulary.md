# Words that help you ask for what you want

Read this reference when composing the final part of a meditation. Help the user name a desired outcome, behaviour, structure or constraint precisely enough for the AI to work out the implementation. Knowing a useful term should reduce the detail they need to specify. It should not require them to learn the whole subject or supervise every technical step.

## Select from the diagram

Every term on this page labels a box or arrow on the study's diagram, usually as the technical name in brackets on a box or as the words on an arrow. Plan the diagram labels and the vocabulary together, so the term that names a part is the term the reader learns. If a useful term names nothing on the diagram, leave it out. Do not add a box or arrow only to hold a term.

From those labels, look at the actual corrections, underspecified requests and decisions. Choose a few terms only when each would give the user useful control over a future task. Prefer terms for parts where the user's decisions changed something, because those are the parts they are most likely to direct again. Prefer words they have not already shown they understand; one correction does not establish a general lack of knowledge. Do not repeat a term merely to fill the page or turn the reflection into a subject glossary.

Select across the work actually done: writing, sound, visuals, personal organisation and software are all eligible. Avoid internal syntax, framework names and implementation details unless knowing them would change a direction the user needs to give. Reuse brief-me’s intention without invoking its full workflow. No fixed term count, three-bucket glossary, new project interview, running metaphor or prerequisite study session is needed.

A term guides interpretation; it does not guarantee correct execution or replace the desired result. Use the technology and constraints established in the session. “Component” alone does not prescribe React; a request for a reusable part can be implemented differently in different projects. Explain a remaining choice only where the choice matters to the user. Do not claim missing vocabulary caused an earlier failure unless the evidence supports that explanation. Identify a newly suggested use as a next-time example, not something that happened.

## Make each term usable

Title the final page “Words that help you ask for what you want”. For each selected term, connect:

- Where it appears on the diagram, in a plain sentence that uses the box's or arrow's own words, such as “This is the name in brackets on the box ‘Card shared by all six books’.” A small copy of the diagram with that part highlighted may replace or support the sentence.
- The concrete result the user might want.
- The term, with a plain explanation that contains no unexplained jargon.
- What it directs the AI to execute in the current kind of task.
- A short instruction the user could actually use next time.

Use a compact comparison or small concrete visual where it makes the connection easier to see. These content requirements need not become repeated labels or a dense table. Keep the existing study’s visual system and readable type. Include one combined example instruction only if the selected requirements fit together. An optional further-study question must help with future direction and fit on this page; do not append a curriculum or mandatory exercise.

For example, in a session that already uses React, the diagram might include the box “Card shared by all six books (reusable component)”. A “reusable component” is a part built once and used in several places. It directs the AI to implement the shared appearance and behaviour together, leaving the internal code structure to the AI. The page says that this is the name in brackets on that box, and gives a possible next instruction: “Make these cards a reusable component so I can change their appearance in one place. Keep each card’s own title and image.” Which details should differ between cards remains a useful choice for the user to specify. This is an illustration, not a default term or subject for every meditation.

## Keep it proportionate

Create one final reference page across the whole meditation, after all topics. It must fit at most one readable A4 page; edit the selection and wording instead of shrinking type. Let it scroll naturally on phones. Count it separately from the topics, and preserve their page limits. Apply the same language, offline, no-JavaScript and print checks as the rest of the study.

If there are no useful new terms, say briefly in the delivery that no additional vocabulary is needed for this task and omit the page. If the user explicitly opts out of vocabulary, omit it without arguing or filling its place. For text-only output, give a compact version after the topics with the same selection and omission rules, naming the part in the numbered list of parts where each term appears. Creating the page does not authorise saving its terms anywhere else or changing any skill, memory or standing instruction.
